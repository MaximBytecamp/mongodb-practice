# Практическая работа 01 · Каталог товаров: витрина и правки

После модуля 1 справочника: подключение, документ, вставка, чтение, проекция,
сортировка со страницами, обновление и удаление.

Две задачи — обе из обычной работы бэкендера, а не из учебника.

## Что дано

База `shop` — эталон, только для чтения: `products` 21, `orders` 120,
`customers` 20. База `sandbox` — копия товаров, её можно менять.
Данные заливаются одной командой и всегда одинаковые:

```bash
bash ../stend/load.sh
```

## Задача 1. Витрина каталога

Напишите функцию, которая возвращает **одну страницу списка товаров** — ровно
то, что бэкенд отдаёт фронтенду:

```python
catalog_page(category=None, page=1, per_page=5, sort_field="price", desc=True)
# → (items, total)
```

Требования:

1. фильтр по категории — необязательный: без него возвращается весь каталог;
2. в ответ идут только поля `sku`, `title`, `price`, `rating`, без `_id`;
3. сортировка по указанному полю, направление задаётся параметром;
4. страницы через `skip`/`limit`;
5. вторым числом возвращается `total` — сколько всего товаров под фильтром
   (без него на странице не нарисовать «2 из 5»);
6. запрос за несуществующей страницей возвращает пустой список, а не ошибку.

**Подсказка, которая экономит час отладки.** Сортируйте по двум ключам:
`[(sort_field, -1), ("sku", 1)]`. При сортировке только по цене товары с
одинаковой ценой могут поменяться местами между двумя запросами — и один и тот
же товар покажется на двух страницах подряд, а другой пропадёт.

## Задача 2. Приёмка поставки

Скрипт, который принимает поставку и печатает отчёт. Работает в `sandbox`:

| Шаг | Что сделать | Чем |
|---|---|---|
| 1 | Прибавить пришедшее количество к остаткам трёх артикулов | `$inc` |
| 2 | Завести две новые позиции каталога | `insert_many` |
| 3 | Снять с продажи артикул `SKU-CP-018` | `count` → `find` → `delete_many` |
| 4 | Поставить всем аксессуарам `free_shipping: true` | `update_many` |
| 5 | Напечатать отчёт с числами по каждому шагу | результаты операций |

Требования:

- остатки увеличиваются **на сервере** (`$inc`), а не чтением-записью из Python:
  иначе при одновременной работе двух приёмок часть товара потеряется;
- повторный запуск скрипта **не должен создавать дубли** — у новых позиций
  задан свой `_id`, поэтому вторая попытка упирается в `E11000`;
- перед удалением — посчитать и показать, что именно будет удалено;
- в отчёте числа берутся из результатов операций (`modified_count`,
  `deleted_count`, `inserted_ids`), а не пишутся руками.

## Как запустить

```bash
bash ../stend/load.sh          # чистые данные
python3 solution.py            # эталонное решение
python3 check.py               # самопроверка
```

Нужен `pymongo`: `pip install pymongo`. Адрес сервера по умолчанию
`mongodb://localhost:27017`, другой задаётся переменной `MONGO_URI`.

## Что должно получиться

`check.py` печатает 12 строк и в конце «Пройдено 12 из 12». Ключевые числа:

| Проверка | Значение |
|---|---|
| товаров в `shop.products` | 21 |
| ноутбуков | 5 |
| самый дорогой товар | Ноутбук Apple MacBook Air 13 |
| позиций в песочнице после приёмки | 22 |
| аксессуаров с бесплатной доставкой | 5 |
| остаток `SKU-NB-001` / `SKU-PH-006` / `SKU-PR-010` | 5 / 12 / 3 |
| изменений в эталонной базе `shop` | 0 |

Последняя строка — не формальность. Если она не сошлась, значит, правки ушли
не в ту базу, и это ровно та ошибка, которая в проекте стоит дороже всего.
